# AURA GLASS — неизменная подпись релиза и переход с debug APK

**Важно:** существующие alpha APK подписаны временными Android debug-ключами GitHub runners, то есть их сертификаты меняются. Обновление установленной alpha поверх неё может вызвать «Приложение не установлено». Мы проверили разные сертификаты v0.1 и v0.2.2.

## Ключ релиза

Создаётся один раз владельцем проекта и хранится в двух защищённых резервных копиях. **Никогда не помещайте .jks/.p12 в публичный GitHub**.

GitHub → `crakacr-alt/AuraGlass` → Settings → Secrets and variables → Actions → New repository secret:

- `AURA_KEYSTORE_B64`: Base64 содержимого полного keystore-файла
- `AURA_STORE_PASSWORD`: пароль keystore
- `AURA_KEY_ALIAS`: alias ключа
- `AURA_KEY_PASSWORD`: пароль ключа

GitHub Actions восстанавливает keystore из секрета во временную папку и стирает после сборки. Подпись релиза проверяется через `apksigner verify --verbose --print-certs`. Публикация заблокирована, пока секреты отсутствуют.

**Важное ограничение инструментов:** через подключённый GitHub API в этом чате невозможно менять GitHub Actions Secrets. Владелец должен однократно добавить их через защищённые настройки GitHub. Не присылайте содержимое секретов в чат.

## Обновление

- Одна стабильная подпись + тот же `applicationId` + растущий `versionCode`.
- Проверка новых **stable**, а не prerelease, версий через GitHub `releases/latest`.
- Перед загрузкой проверяется URL, после загрузки — SHA-256 и совпадение сертификата установленного приложения. Если подписи не совпадают, установка не предлагается.
- Установка APK требует системного подтверждения пользователя. Никаких скрытых установок, root или Accessibility.

**Первый переход с текущих debug-alpha:** может потребоваться удалить несовместимую alpha. Удаление стирает локальные настройки AURA, поэтому сначала сохраните их через экспорт, когда такой экспорт будет реализован, или используйте чистое тестовое устройство.

Не выпускайте `v1.0` до реального теста на Samsung и прохождения критериев из `RELEASE_PLAN.md`.
