# AURA GLASS — дорожная карта до инженерных 100% (кроме подписи)

Обновлено: 10.11.2026. Источник требований: задачи владельца и эталонные изображения AURA GLASS / ICE GLASS.

## Что означает «100%»

**100% — не обещание фотореализма на всех устройствах**, а закрытие всех обязательных требований, воспроизводимые тесты и приемка пользователем на целевом Samsung Galaxy S24 Ultra. Условный прогресс по строкам из старой оценки 25–65% не заменяет доказательства. Пока пункт не подтвержден автоматическим тестом и тестом на железе, оставляем `[ ]`, даже если код есть.

**Подпись — отдельный блокер, не входит в эту инженерную оценку.** Но без постоянного release-keystore нельзя выпустить устанавливаемый поверх прежней версии production APK. Никаких «100% готово» до проверки обновления подписанной предыдущей версии.

### 120 Гц — отдельный блок приёмки

- [x] Режимы выбора в редакторе: «Система», «60 FPS», «120 FPS»; 120 недоступен, если физический экран не поддерживает его.
- [x] Определение поддерживаемых режимов без изменения разрешения; запрос частоты через `WindowManager.LayoutParams.preferredRefreshRate` для интерфейса и `Surface.setFrameRate` для живых обоев на Android 11+.
- [x] `RenderBudget` учитывает кадр ~8,3 мс для 120 Гц и снижает нагрузку при пропусках, сильном нагреве, энергосбережении и Reduce Motion.
- [ ] **Фактические 120 FPS:** измерение Perfetto/FrameTimeline, UI и Wallpaper на реальном Samsung Galaxy S24 Ultra с включённой адаптивной плавностью; не путать поддержку API и достигнутый FPS.
- [ ] Плавное переключение 120→60→30 FPS и обратно, без зависания, микрорывков, троттлинга и повышения температуры.
- [ ] Живые обои/ледяное тепло/звуковая волна/Island/жесты стабильно работают при 120 Гц; при тяжёлой сцене не менее 95% кадров в согласованном бюджете либо явное понижение частоты.
- [ ] Не нарушать системную опцию ограничения частоты, DND, Battery Saver и пользовательскую настройку «Уменьшить движение».
- [ ] На 60-Гц и 90-Гц устройствах нет запроса неподдерживаемых 120 Гц и расхода как в режиме 120.

**Ограничение Android:** запрос 120 Гц — пожелание приложений; One UI/Android может выбрать другой режим. Самый дорогой Canvas-эффект по-прежнему нужно профилировать и, возможно, переводить на GPU до стабильного 120 FPS.

## Как должны работать обновления (строго по запросу владельца)

1. **Только при открытии иконки AURA GLASS** (`SetupActivity.onCreate`), а также при явном нажатии «Проверить сейчас». Не при включении телефона, не при каждом открытии экрана Home, не по таймеру, не через фоновые WorkManager/AlarmManager.
2. HTTPS запрос к `/repos/crakacr-alt/AuraGlass/releases/latest`; GitHub возвращает только опубликованный стабильный релиз, без alpha/beta/prerelease. Сравнение `major.minor.patch`.
3. Если актуально или нет сети — тихое текстовое состояние в разделе обновлений, **без всплывающего ложного предупреждения**.
4. Если новее — заметная карточка «Доступна AURA vX.Y.Z» и кнопка **«Скачать новую версию»**. APK загружается через системный `DownloadManager` по `browser_download_url`. Установка автоматически не начинается.
5. После загрузки пользователь нажимает «Проверить APK и установить»: SHA-256 из GitHub release metadata, размер, пакет `com.auraglass.app`, `versionCode` и совпадение сертификата текущего приложения проходят проверку. Несовпадение — жёсткий отказ, ссылка на объяснение.
6. Только после проверки открыть **системный диалог установщика Android**. Если разрешение «Установка неизвестных приложений» не предоставлено — Android сам предлагает настройку; после возвращения пользователь повторно нажимает «Установить». Никакой тихой установки, никаких обходов.
7. Опционально: тумблер **«Показывать обновления в шторке»**. Android 13+ спрашивает `POST_NOTIFICATIONS` только при включении. Уведомление создаётся при входе в приложение и наличии обновления; не фоновый push. По нажатию открывается AURA.
8. При старом несовместимом debug-подписанном APK обновление блокируется честным сообщением, **без попытки подменить подпись**. Сохранение настроек и миграция разрабатываются отдельно.
9. На GitHub пока **нет стабильного релиза** — только prerelease v0.x alpha. Поэтому механизм правильно пишет «Стабильный релиз пока не опубликован»; реальную установку можно испытать после выпуска пары совместимо подписанных стабильных APK.
10. Если в будущем приложение будет распространяться в Google Play, обновления через Play (In-App Updates) заменят собственный APK-инсталлятор согласно правилам магазина.

## Порядок реализации

**Этап A — надёжность:** установочные сценарии, навигация, возврат к One UI, настройки/бэкап, восстановление после сбоя.

**Этап B — ICE GLASS:** завершение GPU/Canvas гибрида, тонкие кристаллы, ледяная оптика, динамическое сияние, снег и интерактивный тест. Отдельные golden-кадры и 60/120 fps.

**Этап C — рабочий стол и виджеты:** домашние страницы, иконки, папки, AppWidgetHost, поиск и жесты.

**Этап D — Island + звук:** полноценное медиасостояние, уведомления, системный микшер, тесты звонков и альтернативных приложений.

**Этап E — интеграции и безопасность:** модульная схема виджетов, опциональные источники и доступы, offline, запись/экспорт конфигурации.

**Этап F — приёмка:** API 26/29/33/35/36 (если SDK доступен), Samsung S24 Ultra и второй ARMv7 аппарат, проверки памяти/энергии, GIF/видеодоказательства эффектов, regression suite и закрытие всех P0.

Подпись по-прежнему **в отдельной блокирующей задаче**: приватный ключ GitHub Actions, сертификат не должен меняться между версиями, секреты никогда не находятся в репозитории.
